# Running F10 on real data

F10 asks whether Chen, Chen and Li (2026) replicate on your sample. It runs bonds, stocks and accounts only, with no options.

## Run it

```bash
pip install -e .                 # from the repo root, for e2c_data
cd notes/finkelstein_plan
export E2C_DATA_ROOT=/path/to/tables          # or E2C_SOURCE=your_package.module:make_source
python run_f10.py --start 2002-01-01 --end 2021-12-31 --out results
```

Read `results/summary.txt` first. The verdict is near the top, after the run's dates.

- Exit code 0 means the run finished, whatever the verdict.
- Exit code 2 means `check_source` failed a required check. `results/contract.csv` says which one.
- `--force` runs past a failed check, and the summary then says FORCED.
- `pytest test_fk_f10.py` runs the real F10 test only when `E2C_F10_ROOT` names a table folder.

## Tables it reads

| Need | Kinds |
|---|---|
| Required | `security_map`, `universe`, `equity_prices`, `accounts`, `rates` (curve `treasury_par`), `bond_terms`, `bond_prices` |
| Dead names | `events`, with `realised_recovery` and `delisting_return` |
| Dividends and splits | `corporate_actions` |
| Screens | `issuer_attributes`, `bond_trades`, and the flags in `bond_terms` |
| Financing and fee split | `financing` |

Columns and units are in `e2c_data/schema.py`. An absent optional table does not stop the run. The summary names what it could not do.

These cost real results if they are wrong:

1. `dividends`, `interest` and `repurchases` must be trailing 12 months.
2. `seniority` must say `senior_unsecured`, `currency` must say `USD`, and `coupon_type` must say `fixed`. Other words fail the terms screen, so check the funnel in `screens.csv`.
3. A survivors-only universe fails the contract check, and this stop is deliberate.

## What the verdict means

The plan's rule is "Signs must match. Sizes as shape, if samples differ."

- **REPRODUCED:** Q1 gap below 0, Q5 gap above 0, Q1 price ratio below 1, Q5 above 1, bond premium above 0, stock premium above 0. I added that the bond premium's t must reach 1.96. All are read on 2002-01 to 2021-12, value-weighted, 1-month hold, gross.
- **NOT REPRODUCED:** at least one fails. The summary names which.
- **NOT JUDGED:** under 60 months in the window, a median under 25 firms sorted, or a number that could not be computed.

Both continuous and semiannual yields run, because the compounding is undecided. The overall verdict is the weaker of the two.

If signs fail, the plan says to stop and debug before any option work.

## Limits

- No copy of the paper was on hand. Its screens, clean-return definition and standard errors are unknown here, so a miss may be a definition gap. All published figures come from the plan.
- t-statistics are Newey-West with 6 lags. The plan states no method.
- Costs fall back to planning figures of 18 and 68 bp when `bond_trades` has no customer buy and sell flags. The summary says which it used, and a stop-rule result on planning costs is not the plan's measured test.
- Measured bond cost is customer buy less sell per bond-day, so it covers only days with both sides.
- Financing needs 90% of each side's weight to have a rate, and scales up the covered part. Overlay and financing are reported beside the gross return, and they do not change the verdict.
- A bond dropped by the screens stays out of that month's firm average.
- Runtime is about 15 ms per bond-month per compounding. A million bond-months is roughly 8 hours for the two runs, in one process.
- Memory: each kind except `bond_trades` is read whole, once. `--no-liquidity-screen` skips the trades. It also drops measured bond costs.
